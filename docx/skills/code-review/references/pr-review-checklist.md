# PR 审查完整清单

## 1. 概览（先看全局）

- [ ] PR 标题清晰，描述了做了什么
- [ ] 改动范围合理（不超过 500 行，超过应拆分）
- [ ] 只做一件事（不混合功能开发和重构）
- [ ] 没有无关文件被修改

## 2. 安全（P0）

- [ ] 无 SQL 注入风险（所有查询参数化）
- [ ] IPC 输入有 Zod 校验
- [ ] 无硬编码密钥/Token
- [ ] 文件路径操作有边界检查（不允许 `../` 遍历）
- [ ] 日志中无敏感信息
- [ ] 新增的外部依赖无已知漏洞

## 3. 正确性（P0-P1）

- [ ] 边界条件处理（空数组、null、undefined、空字符串）
- [ ] 错误路径有处理（try-catch 或返回 null）
- [ ] 异步操作有错误处理
- [ ] 数据库操作有事务保护（多步写入）
- [ ] 事件监听器有清理（useEffect return、removeListener）
- [ ] 没有竞态条件（并发写入同一资源）

## 4. 性能（P1）

- [ ] 数据库查询有索引支持
- [ ] 没有 N+1 查询（循环中查数据库）
- [ ] 大数据量有分页
- [ ] 文件操作有流式处理（>1MB 文件）
- [ ] React 组件无不必要的重渲染
- [ ] 没有内存泄漏（定时器、监听器未清理）

## 5. 可维护性（P2）

- [ ] 函数不超过 50 行
- [ ] 参数不超过 3 个
- [ ] 命名清晰（读代码不需要看注释就能理解）
- [ ] 没有重复代码（>3 行相同逻辑应提取）
- [ ] 类型定义完整（无 any）
- [ ] 导入顺序正确

## 6. 测试（P2）

- [ ] 新功能有单元测试
- [ ] 测试覆盖 happy path + 至少一个 error path
- [ ] 测试命名清晰（`should xxx when yyy`）
- [ ] 测试独立（不依赖执行顺序）

## 7. UI（如果涉及前端）

- [ ] 深色/浅色主题都正常
- [ ] 空状态有提示
- [ ] 加载状态有指示
- [ ] 错误状态有友好提示
- [ ] 响应式（窗口缩放不破版）
