## 技术决策记录

| 决策 | 选择 | 原因 |
|------|------|------|
| Electron 版本 | 33.x（非最新 42.x） | 42.x 与 better-sqlite3 的 V8 API 不兼容 |
| better-sqlite3 版本 | 11.7.2（非最新 12.x） | 12.x 无法为 Electron 编译 |
| preload 输出格式 | CJS（非 ESM） | Electron preload 沙箱不支持 ESM |
| 窗口加载 URL | `process.env['ELECTRON_RENDERER_URL']` | electron-vite 自动设置，比硬编码 localhost:5173 可靠 |
| externalizeDepsPlugin | 不使用，手动配置 external | 该插件在 electron-vite 5 + vite 8 下有兼容性 bug |
| initDatabase 签名 | 接受 dbPath 参数 | 解耦 Electron API，为未来前后端分离做准备 |
| 架构方向 | 未来 Monorepo | V1.3 时迁移，当前保持单项目结构 |

## 经验教训

1. **Electron 项目的第一件事是确认版本兼容性** — 先查 native 模块支持哪个 Electron 版本，再开始开发
2. **不要用最新版** — Electron、vite、electron-vite 都选稳定版，社区验证过的组合
3. **preload 是特殊环境** — 既不是纯 Node.js 也不是纯浏览器，有自己的限制
4. **构建配置出问题时，先看输出文件内容** — `cat out/preload/index.js` 看是 ESM 还是 CJS 就能定位问题
5. **pnpm 的严格模式是好事但需要适应** — 依赖必须显式声明在 package.json 中，不能靠幽灵依赖
